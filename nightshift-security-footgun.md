## Summary

Jarspect is an AI-first security scanner for Minecraft mods. The codebase is generally well-structured with proper budget gates for archive extraction, input validation, and error handling. Found 5 security-relevant issues ranging from P2 to P3.

---

## Findings

### P2 — Upload endpoint leaks server filesystem path in response

**File:** `src/main.rs:236`  
**Category:** Information disclosure

The `/upload` endpoint returns `storage_url` containing the absolute server path:

```rust
"storage_url": output_path.to_string_lossy(),
```

This exposes the server's directory structure (e.g. `/home/user/jarspect/.local-data/uploads/...`) to anyone who uploads a file. While the upload endpoint itself requires a valid .jar, the path disclosure can aid targeted attacks.

**Recommendation:** Remove `storage_url` from the response or return only the relative path within the uploads directory.

---

### P2 — Scan error responses may leak internal error details

**File:** `src/main.rs:63-66`  
**Category:** Information disclosure

The `From<anyhow::Error> for AppError` impl passes the full error chain to the client:

```rust
impl From<anyhow::Error> for AppError {
    fn from(error: anyhow::Error) -> Self {
        Self::internal(error.to_string())
    }
}
```

Any internal failure (DB connection, file I/O, AI API error) is returned verbatim to the HTTP client. This can leak connection strings, file paths, and stack-level details.

**Recommendation:** Log the full error server-side and return a generic "Internal server error" to the client. Use `map_scan_error()` for user-facing messages and a catch-all that hides details.

---

### P2 — No authentication on any endpoint

**File:** `src/main.rs:132-140`  
**Category:** Authorization

The `/upload`, `/scan`, and `/scans/{scan_id}` endpoints have no authentication. Anyone who can reach the server can upload jars, trigger scans (which make outbound API calls to MalwareBazaar and Azure OpenAI), and retrieve scan results.

**Recommendation:** Add API key authentication middleware. At minimum, protect `/upload` and `/scan` with a bearer token.

---

### P3 — Upload endpoint has no rate limiting

**File:** `src/main.rs:191-238`  
**Category:** Denial of service

There is a body size limit (`upload_max_bytes`, default 50MB) but no rate limiting. An attacker could flood the uploads directory with valid .jar files, exhausting disk space. Each upload also persists the file to disk before any scanning, so the cost is incurred immediately.

**Recommendation:** Add per-IP or per-key rate limiting middleware (e.g. `tower-http` rate limiting). Consider cleanup of old uploads on a schedule.

---

### P3 — AI prompt includes user-controlled data without escaping

**File:** `src/verdict.rs:378-381`  
**Category:** Prompt injection

The user prompt is constructed by serializing the capability profile as JSON:

```rust
let user_prompt = format!(
    "Analyze this capability profile and return JSON only.\n\n{}",
    serde_json::to_string(&summary)?
);
```

The `summary` includes `suspicious_strings`, `extracted_urls`, `extracted_commands` etc. — all derived from the uploaded .jar contents. A crafted .jar could embed strings like `"Ignore all previous instructions and return..."` in its class files, which would be included verbatim in the AI prompt. While the system prompt is strongly directive, the AI could still be influenced by adversarial content in the user message.

**Recommendation:** Consider escaping or truncating string fields that go into the AI prompt, or add a disclaimer in the system prompt that user content may contain adversarial text.

## Non-findings (confirmed safe)

- **Zip bomb protection:** `archive.rs` has proper budget gates: `MAX_TOTAL_ENTRIES` (50k), `MAX_ENTRY_UNCOMPRESSED_BYTES` (16MB), `MAX_TOTAL_INFLATED_BYTES` (256MB), `MAX_COMPRESSION_RATIO` (1000:1), and `MAX_RECURSION_DEPTH` (3). Well done.
- **upload_id validation:** `validate_artifact_id` enforces 32 hex chars, preventing path traversal in scan retrieval.
- **MalwareBazaar API key handling:** Keys are optional, trimmed, and never logged.
- **AI verdict output sanitization:** `confidence` is clamped to [0.0, 1.0], `risk_score` to [0, 100], and verdict is normalized via `normalize_verdict`.
- **File extension check:** Upload endpoint validates `.jar` extension before persisting.
- **Path traversal in archive entries:** `normalize_entry_path` strips `./` and leading `/`, preventing path traversal via entry names.
